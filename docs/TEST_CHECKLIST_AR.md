# Checklist قبل الإطلاق الرسمي

اختبر بحسابات وهمية على الأقل: عضو عادي، رئيس مكتب/لجنة، سكرتير، GS، President، Admin.

## الدخول والعضوية
- [ ] الدخول بالبريد + كلمة السر.
- [ ] الدخول بالرقم الجامعي + نفس كلمة السر.
- [ ] الحساب المستورد يُجبر على تغيير كلمة السر أول مرة.
- [ ] العضو يستطيع تغيير بريده بعد إدخال كلمة السر الحالية.
- [ ] العضو يستطيع تغيير كلمة السر بعد إدخال القديمة.
- [ ] تسجيل الخروج يعمل من بوابة العضو ومن مساحة العمل.
- [ ] السكرتير/رئيس المكتب/GS/President يدخلون بوابة العضو أولًا، ثم يظهر لهم زر «مساحة العمل».

## RLS وفصل الأدوار
- [ ] العضو العادي لا يدخل مساحة العمل.
- [ ] رئيس المكتب/اللجنة يرى مشاريعه المكلف بها فقط، ولا يرى كل سكرتاريته.
- [ ] السكرتير يرى ويدير سكرتاريته فقط.
- [ ] السكرتير الآخر لا يرى المشروع إلا عندما يوجد طلب صلاحية ضمن اختصاصه، وعندها يرى ما يكفي للقرار.
- [ ] GS وPresident يريان الصورة العامة.
- [ ] GS/President لا يستطيعان تنفيذ Intervention أو Verification بدل السكرتير.

## دورة المشروع والنتيجة
- [ ] السكرتير ينشئ مشروعًا بنتيجة + معيار نجاح + deadline + مسؤول نتيجة.
- [ ] مسؤول النتيجة يرى التكليف قبل بدء المشروع.
- [ ] مسؤول النتيجة يستطيع قبوله.
- [ ] مسؤول النتيجة يستطيع إعادته للسكرتير بملاحظة إذا كانت النتيجة/الموعد تحتاج تعديلًا.
- [ ] السكرتير يعدل التكليف ويعيد إرساله.
- [ ] بعد القبول ينتقل المشروع إلى CO_DESIGN.
- [ ] السكرتير ومسؤول النتيجة يستطيعان إضافة Milestones في مرحلة التصميم.
- [ ] لا يبدأ التنفيذ قبل قبول التكليف ووجود Milestone واحدة على الأقل.
- [ ] لا يقبل النظام Milestone موعدها بعد موعد النتيجة النهائي.
- [ ] السكرتير هو من يفعّل المشروع بعد الاتفاق على المسار.

## الصلاحيات
- [ ] الصلاحيات الأصلية تظهر ACTIVE تلقائيًا لمسؤول النتيجة.
- [ ] صلاحية خاصة داخل السكرتارية يطلبها المسؤول فتنتظر سكرتير المشروع.
- [ ] صلاحية cross-secretariat تنتظر سكرتير المشروع + سكرتير الاختصاص الآخر.
- [ ] إذا طلب سكرتير المشروع الصلاحية cross-secretariat تبقى موافقة السكرتير الآخر فقط.
- [ ] صلاحية Executive Committee لا تُفعّل إلا بقرار مسجل.
- [ ] بعد اكتمال الموافقات تصبح الصلاحية ACTIVE ولا تحتاج إذنًا لكل خطوة.
- [ ] رفض أي مرحلة يجعل الصلاحية REJECTED.

## المتابعة والتدخل المبكر
- [ ] مسؤول النتيجة يحدث health + واقع التنفيذ + الخطوة التالية + next check.
- [ ] مسؤول النتيجة يستطيع طلب دعم قبل التأخير.
- [ ] مسؤول النتيجة يسجل Blocker فور ظهوره.
- [ ] العائق/طلب الدعم يظهر على مستوى المشروع للسكرتير.
- [ ] السكرتير يستطيع Intervention حتى قبل تجاوز أي deadline.
- [ ] التدخل يتضمن السبب والإجراء وموعد المتابعة القادم.
- [ ] السكرتير يستطيع إغلاق التدخل بعد المتابعة.
- [ ] غياب تحديث > 5 أيام يظهر كإشارة انتباه.
- [ ] تجاوز next check يظهر كإشارة انتباه.
- [ ] اقتراب Milestone خلال 72 ساعة يظهر كإشارة.
- [ ] اقتراب موعد النتيجة يظهر كإشارة.
- [ ] pending permission يظهر ضمن إشارات المشروع.

## Evidence والتحقق
- [ ] مسؤول النتيجة يرفع Evidence نصي/رابط/ملف.
- [ ] الحالة تصبح READY_FOR_VERIFICATION.
- [ ] المسؤول لا يستطيع اعتماد إنجازه بنفسه.
- [ ] السكرتير يتحقق أو يعيد المحطة.
- [ ] عند اكتمال كل Milestones المعتمدة تصبح النتيجة والمشروع COMPLETED تلقائيًا.
- [ ] إذا كان المشروع ناتجًا عن Proposal مجاز يتغير execution_status إلى COMPLETED تلقائيًا.

## GS والرئاسة
- [ ] GS/President يريان كل السكرتاريات في الرقابة العامة.
- [ ] كل إشارة تعرض مسؤول النتيجة والسكرتير معًا.
- [ ] عائق بلا تدخل يشير أوليًا إلى السكرتير.
- [ ] طلب دعم بلا تدخل يشير إلى السكرتير.
- [ ] غياب تحديث بعد وجود تدخل يشير إلى مسؤول النتيجة.
- [ ] صلاحية معلقة تشير إلى جهة الموافقة بدل محاسبة مسؤول النتيجة.
- [ ] الملاحظات الرقابية لا تعدل بيانات التنفيذ.

## المتابعة الدورية
- [ ] «صورة التنفيذ الحالية» تُولد من المشاريع النشطة دون إدخال تقرير موازٍ.
- [ ] تعرض آخر تحديث، القادم، والتدخل المفتوح.
- [ ] السكرتير يرى سكرتاريته، وGS/President يريان الجميع حسب RLS.

## المقترحات
- [ ] أي مستخدم نشط يستطيع تقديم أو رفع مقترح من بوابة العضو.
- [ ] حفظ المسودة يعيدها لمسوداتي ويمكن فتحها لاحقًا.
- [ ] رفع PDF/DOCX يعطي نجاحًا أو خطأ واضحًا ولا يعلق الواجهة.
- [ ] Secretary يطلب تعديلًا أو يرفع إلى GS.
- [ ] مقدم المقترح يرفع Version جديدة دون حذف النسخة السابقة.
- [ ] GS approve/reject/defer/revision.
- [ ] President يرى مسار المقترحات رقابيًا ولا يأخذ مكان GS في المسار العام الحالي.
- [ ] Approved proposal ينشئ execution project في AWAITING_SETUP.
- [ ] السكرتير يهيئ النتيجة والمسؤول والموعد قبل بدء التنفيذ.

## Drive والملفات
- [ ] Word/PDF لا يبطئ حفظ المقترح.
- [ ] Folder المقترح ثابت بالـinternal ID حتى لو تغير العنوان.
- [ ] V1 وV2 لا تختلط بياناتهما.
- [ ] Evidence files تذهب إلى Drive وتحذف من staging.
- [ ] الملفات ليست عامة Anyone-with-link.

## Telegram / Background Jobs
- [ ] Background job ينتقل PENDING → DONE.
- [ ] الفشل يعاد تلقائيًا حتى 5 محاولات.
- [ ] New proposal يذهب للسكرتير المختص لا لكل القيادة.
- [ ] Result assignment يصل لمسؤول النتيجة.
- [ ] إعادة التكليف للتعديل تصل للسكرتير.
- [ ] Permission pending يصل للجهة الصحيحة.
- [ ] Early warning يصل للسكرتير/الرقابة دون تكرار مزعج.
- [ ] الروابط تفتح Member Portal أو Workspace حسب المستلم.

## GitHub
- [ ] push إلى main يشغل Action.
- [ ] build ينجح.
- [ ] GitHub Pages تُحدث بدون رفع ملفات يدويًا.
