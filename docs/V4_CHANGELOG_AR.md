# KMSA v4 — سجل الإصلاحات مقابل قائمة الـ16 بندًا

| # | البند القديم | ما تم في v4 | القرار الإصلاحي |
|---|---|---|---|
| 1 | الهيكلة والمناصب | أضيفت **مناصب/صفات عمل خفيفة** قابلة للإنشاء والتعديل والإيقاف وربط أشخاص بها | لم نبنِ Organogram أو مكاتب/لجان معقدة؛ الصفة توجد فقط إذا أثرت في المتابعة |
| 2 | مسؤوليات المنصب | Duty Templates قابلة لتغيير الاسم والمخرج والدورية والإيقاف | لا Hard-code للائحة؛ السكرتير يغير المستقبل من الواجهة |

| 5 | الاجتماعات الدورية | Event واحد + Attendance مستقل لكل شخص + Notes/Outcomes + دورية قابلة للتعديل | الاجتماع لا يحسب إنجازًا لمجرد انعقاده؛ نحفظ مخرجاته |
| 6 | المهام السريعة | Quick Tasks مستقلة عن المشاريع | لا نحول «جهز خطابًا» إلى Project |
| 7 | المشاريع والنتائج | استمر نموذج v3: نتيجة، مسؤول، Deadline، Milestones، Evidence، Verification | مركز النظام يبقى الإنجاز لا الهيكل |
| 8 | تحديثات المشاريع | Update cadence مستقل عن Deadlines + تنبيهات التأخير | يكشف العمل المتأخر قبل آخر لحظة |
| 9 | التدخل والمساءلة | Blockers + Secretary Intervention + GS signal لغياب استجابة حديثة | نتابع المنفذ والمتابع معًا |
| 10 | المقترحات | UX موحد، تقديم/رفع من Workspace، Template مباشر، PDF/Word، Revision بالبنود أو الملف، Versions | لم نفرض Workflow قانونيًا مختلفًا لكل نوع Proposal قبل اعتماده مؤسسيًا |
| 11 | PDF والأرشيف | Google Docs Master، Document priority، dedupe، idempotency، retry، watchdog، Drive archive | PDF لا ينتظر خلف الإشعارات ولا تبقى Job عالقة بلا نهاية |
| 12 | واجهة السكرتير | «الأولوية الآن» ثم مشاريع/مهام/دوري/مقترحات | لا KPI dashboard للاستعراض |
| 13 | واجهة GS | Control Tower موحدة + فلاتر + Technical readiness | GS لا يحتاج طلب Sheets منفصلة |
| 14 | التقارير | PDF/Print رسمي + مستويات تفاصيل + Tasks/Routine/Proposals + CSV خام | لا تكرار اسم السكرتارية داخل تقرير سكرتارية واحدة |
| 15 | الإشعارات | Inbox داخل النظام للأفعال المطلوبة + dedupe | لا Spam عام |
| 16 | Audit & Readiness | System readiness snapshot + اختبار قبول P0/P1/P2 + static readiness script | Ready قرار مبني على اختبارات لا انطباع |

## ما تم استبعاده عمدًا

- إدارة مكاتب ولجان وهيكل تنظيمي تفصيلي داخل النظام.
- تحويل لجنة مشروع إلى كيان هيكلي منفصل عن المشروع.
- قبول/رفض مسؤول المشروع للتكليف داخل المنصة.
- صلاحيات عامة ظاهرة للمستخدم كقائمة تقنية.
- نظام انتخابات/مالية/شكاوى كامل ضمن v4؛ هذه وحدات مستقلة وليست شرطًا لتثبيت محرك المتابعة الحالي.

## القاعدة التي تحكم أي تطوير لاحق

إذا لم تضف الميزة وضوح مسؤولية، كشفًا مبكرًا، تدخلًا أفضل، دليلًا، أو ذاكرة مؤسسية — فلا تدخل النظام.
