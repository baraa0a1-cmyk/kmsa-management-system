# تحديث KMSA v6.3 — إصلاح تعيين المناصب وقائمة «غير محدد الدفعة»

## ما الذي أصلحناه؟

1. **فشل تعيين الرئيس والسكرتارين** مع الخطأ `operator does not exist: app_role = text`: السبب مقارنة العمود `cycle_memberships.role` (نوعه `public.app_role`) بالمتغير `p_role` (نوعه `text`) داخل `kmsa_admin_replace_leader`. أصلحت الوظيفة المقارنتين بتحويل المتغير إلى `public.app_role` بعد فحص قيمته. التغيير يقع **داخل PostgreSQL**، وليس فقط في الواجهة.
2. أُضيف قسم «غير محدد الدفعة» آخر قائمة الدفعات. يعرض الأعضاء غير الإداريين ممن `profiles.batch_number IS NULL`. يمكن البحث بينهم وفتح ملفهم ونقلهم إلى دفعة موجودة وإعادة تعيين كلمة المرور؛ لا يوجد رقم دفعة وهمي ولا حساب جديد يُنشأ بالقسم.
3. العدد بجانب قسم «غير محدد الدفعة» يأتي من استعلام محمي في قاعدة البيانات.
4. التصنيف لا يضم حساب مدير النظام الدائم (`ADMIN`)؛ فهذا الحساب إداري منفصل عن أعضاء الرابطة.

## مهم: لا تُعد تشغيل الترقيات السابقة

**يُطبّق هذا الإصلاح فوق v6.2 فقط.** قبل أي SQL خذ نسخة احتياطية وجرّب على مشروع Supabase تجريبي. لا تنفذ `0019` أو `0020` أو `0021` مرة أخرى.

### الخطوة الأولى: SQL

في Supabase Dashboard → SQL Editor افتح **`KMSA_V6_3_UPGRADE.sql`** من الحزمة وانسخ محتواه، ثم نفّذه **مرة واحدة**. يوجد المحتوى نفسه في `supabase/migrations/0022_office_enum_and_unassigned_v6_3.sql`؛ **لا تشغّل الاثنين**. لا يحذف الملف أعضاء أو مشاريع أو دفعات أو دورات.

إذا ظهر خطأ متطلبات `V6_3_PREREQUISITES_MISSING` فتوقف: قاعدة البيانات لا تضم جدولًا أو وظيفةً لازمة من الإصدارات السابقة. لا تصنع جدولًا بديلًا يدويًا.

### الخطوة الثانية: نسخ ملفات الواجهة

حمّل `KMSA_v6_3_FIX_UPDATE.zip` وفك الملفات في **مجلد مشروعك الفعلي** فوق v6.2، مع استبدال الملفات. احتفظ بنسخة من مجلد المشروع الأصلي إذا لديك تعديلات خاصة.

### الخطوة الثالثة: جميع أوامر PowerShell المطلوبة

افتح PowerShell وأدخل الأوامر التالية بالترتيب. غيّر مسار المشروع في أول أمر فقط إذا كان مختلفًا:

```powershell
cd "C:\Users\baraa\Desktop\KMSA_Management_System_GitHub_v2"

cd apps\web
npm.cmd ci
npm.cmd run build
cd ..\..

node scripts\v6-3-check.mjs
node scripts\v6-2-check.mjs
node scripts\v6-1-check.mjs

git status
git add .
git commit -m "KMSA v6.3 - fix leadership roles and unassigned members"
git push origin main
```

**إذا فشل البناء أو أحد الاختبارات فلا تنفذ أوامر `git add` أو `git push` حتى تصلح الخطأ.** إذا كان الفرع مختلفًا عن `main` استخدم اسم الفرع الفعلي من `git branch --show-current`.

> لا يحتاج هذا التحديث إلى إعادة نشر Supabase Edge Function `workflow`: لم نعدّل كودها في هذا الإصلاح. تغيير قاعدة البيانات ضروري حتى لو نجح بناء الموقع.

### الخطوة الرابعة: اختبار الاستخدام

1. افتح **الدورات والقيادة**، ثم دورة تشمل دفعة غير متخرجة فيها عضو. افتح «تعيين رئيس الرابطة» وابحث عن العضو واحفظ. يجب ألّا يظهر الخطأ `app_role = text`.
2. جرّب تعيين سكرتير آخر، ثم تغيير الشاغل إلى عضو آخر من دفعة مشمولة. تأكد أن سجل المناصب والصلاحيات قد تحدّثا.
3. افتح **الأعضاء والدفعات → غير محدد الدفعة**. ابحث عن عضو قيمة دفعته فارغة، افتح ملفه وانقله إلى دفعة موجودة. يجب أن يختفي من هذا القسم ويظهر في دفعته الجديدة بعد تحديث الصفحة.
4. تأكد من أن حساب المدير الدائم لا يظهر في قسم الأعضاء دون دفعة.

## حدود الاختبار

تم التحقق من TypeScript والاختبارات الثابتة، لكن **لم يتم تشغيل الترقية على Supabase حي**. لا يمكن ضمان خلو جميع وظائف الإنتاج من مشكلات أخرى دون اختبار عملي في بيئة تجريبية. يشمل الاختبار المطلوب أيضًا تكليف الرئيس والسكرتير فعليًا والتأكد من الصلاحيات بعد التكليف.
