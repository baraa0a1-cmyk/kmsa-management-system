# تثبيت KMSA v6.2 — إصلاح إدارة النظام

## مهم قبل التثبيت

هذه الترقية مخصصة للمشروع **v6.1** الذي بُني فوق إصدارات v5.8 وv5.9 وv6.0. **لا تعِد تشغيل SQL الخاص بالإصدارات السابقة**. خذ نسخة احتياطية من قاعدة البيانات أولًا، وجرّب على Supabase تجريبي قبل نقلها لبيانات الطلاب الفعلية.

## الملفات المطلوبة

- **KMSA_v6_2_ADMIN_UPDATE.zip**: التغييرات فقط فوق v6.1.
- **KMSA_Management_System_v6_2_FULL.zip**: المشروع الكامل بعد الدمج.
- **KMSA_V6_2_UPGRADE.sql**: ترقية قاعدة البيانات الحالية فقط. نسخة مطابقة داخل `supabase/migrations/0021_admin_integrity_v6_2.sql`. **نفّذ أحدهما فقط**.

## التركيب

1. في **Supabase → SQL Editor**، نفّذ `KMSA_V6_2_UPGRADE.sql` مرة واحدة بعد النسخ الاحتياطي؛ يتأكد الملف من وجود وظائف إصدارات 5.8–6.1. **لا تعِد تشغيله إذا فشل بسبب غياب المتطلبات**؛ أصلح الترقية الناقصة أولًا.
2. فك ملف التحديث فوق مجلد v6.1 الحالي واستبدل الملفات. لا تنسَ حفظ أي تغييرات محلية لديك.
3. من PowerShell داخل مجلد المشروع:

```powershell
npx.cmd supabase@latest functions deploy workflow --use-api
cd apps\web
npm.cmd ci
npm.cmd run build
cd ..\..
node scripts\v6-2-check.mjs
```

4. بعد نجاح الخطوات جرّب الموقع قبل رفعه للإنتاج. إذا كان إصدارك على GitHub Pages، ارفع الملفات إلى GitHub لتعمل إجراءات البناء والنشر المعتادة.

## فحوصات القبول المهمة

- ادخل إلى دورة تشمل الدفعة 98 فقط: تعيين عضو من الدفعة 98 يجب أن يكون متاحًا، ومن الدفعة 99 يجب أن يُرفض **من قاعدة البيانات** حتى لو أرسلت طلبًا يدويًا.
- لا تظهر دفعات متخرجة في اختيارات الضم للدورات أو البحث الجديد عن شاغلي المناصب. لكن سجل أعمال وأسماء أعضاء الدفعة المتخرجة يبقى محفوظًا.
- جرّب تعيين رئيس، وسكرتير، ومساعد السكرتير العام في دورة تحت الإعداد ودورة نشطة. تأكد من انتقال الصلاحيات وحفظ سجل تغيّر الشاغلين.
- ارفع CSV يحوي حسابًا جديدًا، وحسابًا قائمًا بالرقم الجامعي نفسه وبريد مختلف، وحسابًا ببريد مستخدم لدى شخص آخر. الجديد قابل للإنشاء، والموجود قابل لاختيار حقول التحديث، والتعارض لا يُعالج آليًا.
- حدد تحديث الاسم فقط، ثم تحديث البريد فقط. تأكد أن كلمة المرور لم تتغير وأن الشخص لم ينتقل إلى دفعة ثانية، وأن بريده في `auth.users` و`public.profiles` متطابق بعد التحديث.
- افتح رسالة خطأ أثناء تعيين قيادة: يجب ظهور رسالة مفهومة في **أعلى النافذة** بدل `[object Object]`، ودون تكرارها أسفل الصفحة.
- اختبر عرض أكثر من 25 اسمًا في مراجعة CSV والبحث عن أشخاص، والتحديد بعد تغيير الاستعلام.

## حدود التحقق

- فحص TypeScript والاختبارات الثابتة لا يثبتان نجاح العمليات على Supabase الحقيقي. يحتاج الأمر بيئة staging باختبار حساب مدير وحسابي عضو على الأقل.
- تحديث البريد بواسطة Supabase Admin API إجراء إداري مباشر. **لا تُحدّث بريد طالب إلى عنوان لم تتحقق أنه يخصه**، لأن البريد يستخدم في دخول الحساب واستعادته. بيانات الملف ليست إثبات ملكية للبريد.
- إن نجح تحديث جزء من عملية جماعية ثم فشل جزء آخر، لا تعِد رفع الملف دون الاطلاع على حالة الحسابات الحالية. يمنع النظام التكرار بالرقم الجامعي، لكن راجع نتيجة كل سجل.
- لا تحذف ملفات قاعدة البيانات أو المشاريع القديمة ولا تبدل الحقول التنظيمية يدويًا من SQL.
