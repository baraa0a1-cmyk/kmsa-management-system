# مساحة العمل التنفيذية — Workspace v1

هذه النسخة تفصل بين **بوابة العضو** و**مساحة العمل**. السكرتير أو رئيس المكتب/اللجنة أو السكرتير العام أو رئيس اللجنة التنفيذية يظل عضوًا أولًا؛ يدخل بوابة العضو كالمعتاد، ويظهر له زر «مساحة العمل» عندما تكون لديه مسؤولية تنظيمية.

## 1) الأدوار

- `APPLICANT` — عضو عادي: بوابة العضو والمقترحات والخدمات العامة.
- `MEMBER` — رئيس مكتب/لجنة أو مسؤول نتيجة: بوابة العضو + المشاريع التي كُلّف بقيادتها فقط.
- `SECRETARY` — سكرتير: بوابة العضو + مشاريع سكرتاريته + مراجعة مقترحاتها + التحقق والتدخل.
- `GS` — السكرتير العام: رؤية جميع السكرتاريات، متابعة التدخلات والانحرافات، وقرار المقترحات بعد رفعها من السكرتير.
- `PRESIDENT` — رئيس اللجنة التنفيذية/الرابطة: رؤية تنفيذية عامة، القرارات المؤسسية، والموافقات التي تحتاج قرار اللجنة التنفيذية.
- `ADMIN` — إدارة تقنية كاملة للنظام.

## 2) دورة المشروع

المشروع لا يبدأ بقائمة مهام. يبدأ بـ:

1. السكرتير يحدد **اسم المشروع، النتيجة المطلوبة، معيار النجاح، الموعد النهائي، ومسؤول النتيجة**.
2. مسؤول النتيجة يراجع التكليف:
   - يقبله؛ أو
   - يعيده للسكرتير بملاحظة إذا كانت النتيجة/المعيار/الموعد تحتاج تعديلًا.
3. بعد القبول ينتقل المشروع إلى **تصميم التنفيذ المشترك**.
4. السكرتير ومسؤول النتيجة يضعان Milestones تكشف مبكرًا هل النتيجة تسير في الاتجاه الصحيح.
5. السكرتير يعتمد المسار ويبدأ التنفيذ.
6. مسؤول النتيجة يحدث **واقع المشروع**: أين وصل؟ ما الخطوة التالية؟ ما نقطة المتابعة القادمة؟ هل يحتاج دعمًا؟
7. الإنجاز لا يعتمد ذاتيًا: يرفع المسؤول Evidence، ثم السكرتير يتحقق من الـMilestone أو يعيدها.
8. اكتمال جميع المحطات المعتمدة يؤدي إلى اكتمال النتيجة والمشروع آليًا.

## 3) الصلاحيات

### صلاحيات أصلية
تُفعل تلقائيًا لمسؤول النتيجة مع التكليف:
- تحديث التقدم.
- المساهمة في تصميم الـMilestones.
- رفع الأدلة.
- تسجيل العوائق وطلب الدعم.
- الاطلاع على ملفات المشروع.

### صلاحيات خاصة
- داخل اختصاص السكرتارية: يمنحها السكرتير؛ وإذا طلبها المسؤول تمر بموافقة سكرتير المشروع.
- متداخلة مع سكرتارية أخرى: تحتاج موافقة سكرتير المشروع + سكرتير الاختصاص الآخر. إذا كان سكرتير المشروع نفسه هو من طلبها فموافقته ضمنية.
- مؤسسية/عابرة للرابطة: لا تُفعل بقرار فردي؛ تُربط بقرار مسجل للجنة التنفيذية.

بعد إجازة الصلاحية تصبح فعالة للمشروع بدل طلب الإذن عند كل خطوة.

## 4) التدخل المبكر

النظام لا ينتظر تجاوز الـdeadline. تظهر إشارات مبكرة عند:
- طلب دعم من مسؤول النتيجة.
- وجود Blocker مفتوح.
- عدم وجود تحديث حديث.
- تجاوز نقطة متابعة اتفق عليها الطرفان.
- اقتراب Milestone.
- اقتراب موعد النتيجة.
- بقاء صلاحية لازمة معلقة.
- تحول المشروع إلى WATCH / AT_RISK / BLOCKED.

السكرتير يستطيع تسجيل Intervention في أي وقت مع السبب والإجراء وموعد المتابعة القادم.

## 5) رؤية GS والرئيس

صفحة الرقابة العامة تظهر لكل مشروع:
- السكرتارية.
- مسؤول النتيجة.
- السكرتير.
- الإشارة الحالية.
- آخر تدخل.
- العوائق والصلاحيات المعلقة.

وتعرض **إشارة مسؤولية** وليست حكم محاسبة آليًا؛ مثل: مسؤول النتيجة لم يحدث، أو طلب دعمًا ولم يظهر تدخل، أو توجد صلاحية معلقة لدى جهة أخرى.

## 6) المتابعة الدورية

لا يوجد نموذج أسبوعي موازٍ في هذه النسخة. «صورة التنفيذ الحالية» تُولد من نفس البيانات التي يستخدمها المشروع: آخر تحديث، المحطة القادمة، العوائق، التدخلات، والمواعيد. بذلك لا يكتب السكرتير نفس المعلومة مرتين.

## 7) المقترحات

المسار الحالي:

`مقدم المقترح → السكرتير المختص → السكرتارية العامة → قرار`

- السكرتير: يطلب تعديلًا أو يرفع المقترح للـGS.
- GS: يجيز/يرفض/يؤجل/يطلب تعديلًا.
- الرئيس: رؤية رقابية للمسار في هذه النسخة.
- عند الإجازة ينشأ مشروع تنفيذ في حالة «يحتاج تهيئة»؛ لا يُعتبر الإنجاز قد بدأ بمجرد الإجازة.
- السكرتير يحدد النتيجة ومسؤولها والموعد ثم تبدأ دورة المشروع أعلاه.

### نقطة تنظيمية مؤجلة
لائحة أعمال اللجنة التنفيذية تضع مسارًا خاصًا لإجازة **تصورات المناشط** يشارك فيه الرئيس والسكرتير العام والمالي. لا نطبقه على كل Proposal تلقائيًا لأن النظام الحالي لا يميز بعد بين «مقترح عام» و«تصور منشط». عند إضافة تصنيف المقترحات سنربط كل نوع بمسار الإجازة المناسب بدل فرض مسار واحد على الجميع.
