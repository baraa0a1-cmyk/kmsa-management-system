# الأدوار ومسؤولية المتابعة — v4

## العضو
يستخدم بوابة العضو. إذا أُسندت له مهمة أو مشروع أو التزام دوري أو صفة عمل نشطة، يظهر له «مساحة العمل» تلقائيًا.

## مسؤول المشروع
هو أي عضو كلفه السكرتير خارج المنصة ثم سجّل السكرتير قرار التكليف واعتمده GS. لا يوجد زر قبول/رفض للتكليف داخل النظام. مسؤوليته أن يرفع تحديثات دورية، يحدث محطات الإنجاز، يسجل العوائق ويقدم الأدلة. لا يعتمد إنجازه بنفسه.

## صاحب مهمة سريعة
يرى المهمة المسندة إليه ويحدث حالتها وملاحظته ودليله دون المرور بنظام Project.

## صاحب صفة عمل
مثل «أمين أكاديمي». الصفة ليست Role تقنيًا ولا Organogram. فائدتها أن يحصل كل شخص يحملها على الالتزامات والاجتماعات المشتركة، مع تتبع مستقل لكل شخص.

## السكرتير — SECRETARY
يدير سكرتاريته فقط: مشاريعها، مهامها، العمل الدوري، المقترحات، التدخلات والتحقق. يرى إشارات الخطر مبكرًا، ويسجل ما فعله عند ظهور مشكلة.

## السكرتير العام — GS
يرى الصورة العابرة للسكرتاريات ويحدد أين توقف التنفيذ: مسؤول، سكرتير، Proposal، التزام دوري، مهمة، أو خلل مستندات. لا يعمل بدل السكرتير في التنفيذ اليومي.

## الرئيس — PRESIDENT
يرى الصورة العامة والسجل الرسمي وما يحتاج مستوى قياديًا، دون دمج دوره مع GS أو تحويله إلى مدير يومي للسكرتاريات.

## Admin
إدارة الحسابات والبنية التقنية والاختبارات. Admin ليس بديلًا إداريًا للرئيس أو GS.

## قاعدة المسؤولية

- مشروع كبير → Project.
- عمل صغير مباشر → Quick Task.
- واجب متكرر → Routine Duty.
- نفس الواجب لمجموعة ذات صفة مشتركة → Position-linked Duty.
- اجتماع المجموعة → Recurring Event مع حضور فردي.

لا نستخدم هيكلًا أعقد إذا كان المسار الأبسط يحقق المتابعة والمساءلة.
