# KMSA v5 — اختبار القبول الإصلاحي

**هدف النسخة**: إظهار واقع التنفيذ، المسؤول عنه، موعد اكتشاف الخلل، تدخل السكرتير، والدليل. لا نختبر شكل المكتب/اللجنة.

## الاختبارات الحرجة (كل اختبار يجب أن ينجح)

| # | التجربة | معيار النجاح |
|---|---|---|
| 1 | عضو يحاول عبر رابط/API تعديل مشروع سكرتارية أخرى | رفض في Backend وليس فقط إخفاء الزر |
| 2 | سكرتير أكاديمي يحاول إدارة مشروع ثقافي | رفض في Backend |
| 3 | سكرتير ينشئ مشروعًا بنتيجة ومسؤول ومواعيد ومحطات | يذهب لاعتماد GS ثم يظهر للمسؤول |
| 4 | المسؤول لا يحدث المشروع طوال دورية التقرير رغم أن Deadline بعيد | يظهر Missing update للسكرتير وGS |
| 5 | مسؤول يفتح Blocker ويرفع التقرير «على المسار» | يرفض السيرفر التناقض |
| 6 | مسؤول يرسل تقدمًا ونصًا دون تحديد خطوة تالية أو دعم | يرفض التقرير الناقص |
| 7 | مشروع محطة CANCELLED وأخرى VERIFIED | لا يعد النظام المشروع مكتملًا ما لم تتحقق جميع المحطات النشطة |
| 8 | المسؤول يرفع ملف دليل والـDrive Bridge معطل | لا تتحول المحطة «جاهزة للتحقق» قبل حفظ الملف بالفعل |
| 9 | السكرتير يسجل تدخلًا بلا إجراء محدد | يرفض السيرفر؛ يسجل الإجراء الفعلي فقط |
| 10 | يظهر تعثر بعد تدخل السكرتير القديم | GS يرى أن استجابة جديدة مطلوبة |
| 11 | سكرتير يسند مهمة بسيطة لشخص | يراها، يحدثها، يرى السكرتير حالتها |
| 12 | مسؤول عمل دوري يرفع تقريرًا «متعثر» | يبقى الاستحقاق متأخرًا، ولا يقفز للموعد المقبل |
| 13 | أمناء أكاديميون متعددون في نفس الالتزام | لكل شخص تسليمه وحالته؛ حضور الاجتماعات فردي |
| 14 | تغيير دورية تقرير مشترك | الماضي محفوظ، والاستحقاقات المستقبلية تتغير |
| 15 | تقديم Form proposal | PDF وWord حقيقيان، مع سجل نسخة محفوظ |
| 16 | رفع PDF ثم فشل الأرشيف واضغط Retry | لا يخلق ملف Word مخالفًا للأصل |
| 17 | الملف غير موجود في Google Drive | لا يدعي النظام نجاح الأرشفة |
| 18 | مستخدم يرسل stagingPath خاصًا بشخص آخر | يرفض العامل الصلاحيات قبل استخدام Service Role |
| 18أ | رفع ملفي دليل مختلفين لهما الملاحظة النصية نفسها | يحتفظ النظام بكل ملف على حدة، ولا يعيد استخدام ملف خاطئ |
| 19 | إنشاء مقترح وتركه لدى السكرتير أكثر من مهلة المراجعة | يظهر تأخره للسكرتير وGS |
| 20 | تعطيل scheduled-monitor ثم استعادته | تُرصد الوظيفة المتوقفة ويعمل استرداد jobs العالقة |
| 21 | توليد PDF يعود دون PDF file ID | يسجل FAILURE وRetry، وليس نجاحًا زائفًا |
| 22 | تصدير تقرير GS | يعرض الاستثناءات والنتائج والتدخلات وليس CSV شكليًا |
| 23 | تحميل قسم المشاريع يفشل أثناء فتح الرئيسية | تظهر رسالة أن صورة المتابعة ناقصة، لا «لا توجد مشاكل» |
| 24 | إنجاز المشروع | كل محطة نشطة VERIFIED، والدليل محفوظ وقابل للمراجعة |

## اختبار عملي غير برمجي
من دون التواصل مع مسؤول العمل، هل يستطيع السكرتير معرفة: آخر تقدم، آخر مخرج، التحدي، الخطوة التالية، وهل تأخر التقرير؟ ومن دون سؤال السكرتير، هل يستطيع GS تحديد المشروعات التي تعثرت ثم لم يتدخل فيها السكرتير؟

**لا READY دون نجاح الاختبارات الحرجة، وفحص RLS حي، وGoogle Drive فعلي، وPilot أكاديمي في بيئة مستخدمين حقيقية.**

## نقاط لا تثبتها الاختبارات الساكنة
- تشغيل Cron وTelegram وفق أسرار وموارد مشروعك.
- صحة مستندات PDF من ناحية التصميم باستخدام Master Template.
- قدرة واجهة العضو والمسؤول والسكرتير على تحمل انقطاع الإنترنت.
- دقة متابعة GS عند تبدل الأشخاص والأدوار خلال الدورة.
- صدق التقارير البشرية، ويحتاج تحقق الأدلة لا مجرد خانة «مكتمل».
