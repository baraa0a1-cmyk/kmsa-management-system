# KMSA v6.1 — تحديث واجهة مدير النظام

## نطاق التحديث
- الإدارة قسمان فقط: **الأعضاء والدفعات**، و**الدورات والقيادة**.
- استخدام شعار كلية الطب الموجود في المشروع مع هوية فحمية/زرقاء/حمراء، وتحسين العرض للهاتف والحاسوب.
- الأعضاء يُضافون من داخل الدفعة؛ يمكن إضافة شخص واحد أو استيراد CSV باختيار الأسماء المراد إنشاؤها فقط.
- تعديل اسم الدفعة ورقمها ومستواها العام مع تعديل جميع الروابط في معاملة واحدة، وحفظ سجل التصحيحات.
- البحث عن الأشخاص على الخادم باسم الشخص أو رقمه الجامعي، مع تصفية حسب الدفعة والترقيم؛ لا يحمل النظام آلاف الأسماء داخل المتصفح.
- إدارة كلمة المرور أو نقل العضو إلى دفعة أخرى من بطاقة الشخص داخل دفعته. لا تُعرض كلمات المرور التي اختارها الأعضاء.
- تعيين شاغلي مناصب اللجنة التنفيذية التسعة عبر البحث بالاسم/الرقم الجامعي والدفعة. لا يُضاف نظام مجلس الرابطة أو متابعة الوضع الأكاديمي الفردي/التجميد.
- اعتماد الدورة الحالية بزر واضح، مع **تأكيد واحد من الموقع**؛ تبقى الحماية وسجل الانتقال وإمكانية الرجوع في قاعدة البيانات وفق ترقية v6 السابقة.
- لا تُنقل المشاريع ولا تُمسح عند اعتماد دورة أخرى.

## متطلبات إلزامية
- المشروع الذي أرسلته سابقًا `5.9.zip` مع إصلاح الدمج الذي استلمته، ويحتوي على ترقية `0019_v6_admin_safety.sql`.
- يجب أن تكون ترقيات 0017 و0018 و0019 **منفذة فعلًا** في قاعدة البيانات. بما أنك نفذت SQL الإصدار السادس سابقًا، **لا تعِد تنفيذه**.
- خذ نسخة احتياطية من Supabase قبل تغيير قاعدة الإنتاج. جرّب أولًا في مشروع Supabase تجريبي مطابق.

## خطوات التركيب
1. انسخ المشروع الحالي إلى مجلد احتياطي مستقل (مع إبقاء مفاتيح البيئة خارج ZIP).
2. من Supabase SQL Editor نفّذ **ملف `KMSA_V6_1_UPGRADE.sql` فقط** (أو migration `0020_admin_essentials_v6_1.sql` عبر نظام migrations؛ لا تشغّلهما معًا). هذه الترقية تضيف إجراء تصحيح الدفعة وبحث الأعضاء وفحص الأعداد؛ لا تحذف مشاريع أو دورات أو حسابات.
3. فك حزمة `KMSA_v6_1_ADMIN_UPDATE.zip` فوق **مشروعك الأخير الذي يعمل**، مع الموافقة على استبدال الملفات.
4. افتح PowerShell داخل المشروع ونفذ:

```powershell
cd apps\web
npm.cmd ci
npm.cmd run build
cd ..\..
node scripts\v6-1-check.mjs
```

5. بعد نجاح البناء والفحص، نفذ:

```powershell
git add .
git commit -m "KMSA v6.1 focused administration redesign"
git push origin main
```

هذه النسخة لا تُعدّل وظيفة `workflow`؛ لذلك لا يتطلب **هذا التحديث تحديدًا** إعادة نشرها إذا كانت نسخة v6 متاحة بالفعل. في حال أن خادمك يستخدم كودًا أقدم فلا يكفي تحديث الواجهة وحدها.

## سيناريوهات القبول
1. يسجل مدير النظام الدخول ويظهر له قسمان فقط، دون المشاريع أو بوابة العضو.
2. ينشئ الدفعة 103، ثم يعدل اسمها ومستواها، ثم رقمها إلى 104 مع التأكد من عدم فقد أي عضو أو علاقة بدورة.
3. يضيف عضوًا فرديًا من داخل الدفعة، ثم ينقله لدفعة أخرى، ويعيد تعيين كلمة مروره.
4. يستورد CSV من صفحة الدفعة ويحدد 3 أشخاص فقط من 200؛ يجب ألا تُنشأ الحسابات الأخرى.
5. ينشئ دورة، ويختار الدفعات المشمولة، ثم يعين الرئيس والسكرتارين عبر البحث دون تحميل كل الأعضاء.
6. يغير سكرتيرًا خلال دورة جارية ويتأكد من سحب صلاحيات السابق وإسنادها للجديد وعدم تبديل مسؤوليات المشاريع التاريخية.
7. يغير الدورة الحالية بنقرة وتأكيد واحد. يراجع بقاء أعمال الدورة السابقة ويجرب الرجوع للدورة السابقة.
8. يحدث خطأ متزامن أثناء اعتماد الدورة؛ يجب أن يرفض الخادم العملية القديمة برسالة واضحة دون فقدان البيانات.

## حدود التحقق
- اجتازت ملفات الواجهة الجديدة TypeScript والتحققات الثابتة في بيئة العمل.
- **لم يتم اختبار الترقية SQL على قاعدة Supabase فعلية**.
- **تعذر بناء Vite محليًا** لأن `node_modules` المسترجعة من جهاز Windows تحتوي Rollup خاصًا بـWindows، بينما بيئة العمل Linux. GitHub Actions تستخدم `npm ci` نظيفًا على Ubuntu.
- لا تعتبر هذه النتائج موافقة على الانتقال إلى الإنتاج قبل تنفيذ سيناريوهات القبول أعلاه على قاعدة بيانات اختبار.
