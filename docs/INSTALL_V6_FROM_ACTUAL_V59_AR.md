# KMSA — إصلاح الدمج فوق النسخة المرفقة فعليًا (v5.9 + أجزاء v6)

## ما الذي وجدناه؟

الملف المرفق `5.9.zip` يحتوي مسبقًا على migration `0019_v6_admin_safety.sql` ومكونات إدارة v6. نص SQL الذي أُرسل منفصلًا مطابق لمحتوى الملف داخل المشروع.

فشل البناء الحالي كان بسبب بقاء JSX قديم مخفي داخل `AdminPage.tsx` بالسطر 86، وينتج ثلاثة أخطاء TypeScript: `TS18048`.

## ماذا تفعل؟

1. **لا تعِد تنفيذ SQL v6**. تحقّق فقط من نجاح تنفيذه عبر استعلام التشخيص الموجود في `docs/V6_DATABASE_STATUS_READ_ONLY.sql`.
2. استخدم **النسخة الكاملة المصححة** أو انسخ ملفات حزمة الإصلاح على نسخة المشروع المطابقة. لا تُعد تطبيق `scripts/apply_v6_admin.mjs` لأن الإضافات موجودة مسبقًا.
3. أغلق PowerShell في جذر المشروع ثم شغّل:

```powershell
cd "C:\Users\baraa\Desktop\KMSA_Management_System_GitHub_v2\apps\web"
npm.cmd ci
npm.cmd run build
cd ..\..
node scripts\v6-integration-check.mjs
```

4. بعد نجاح GitHub Actions انشر وظيفة `workflow` من ملفات المشروع المصححة، **إذا لم تكن منشورة بعد**:

```powershell
npx.cmd supabase@latest functions deploy workflow --use-api
```

5. ادفع التغييرات إلى GitHub بعد التأكد من عدم وجود كلمات مرور أو ملفات `.env` داخل تغييرات Git:

```powershell
git status
 git add .
 git commit -m "Fix v6 admin integration and CSV checks"
 git push origin main
```

## اختبار قبول بعد النشر

- تسجيل الدخول بحساب مدير النظام والانتقال مباشرةً لإدارة الدفعات والدورات.
- فتح دورة حالية: تظهر بطاقة «الدورة المعتمدة لمساحة العمل» وليس زر التفعيل القديم.
- فتح دورة أخرى: يعرض النظام الدورة الحالية والجديدة، ويطلب كتابة رمزها قبل الاعتماد.
- لا تجرب تغيير الدورة الفعلية إلا في نسخة تجريبية من البيانات أولًا؛ التغيير يعيد حساب صلاحيات القيادة الحالية.
- ارفع CSV مرتين باسم الملف نفسه: يجب فحص التكرارات في المرتين، وعدم السماح باختيار اسم قبل نجاح التحقق.
- أضف عضوا فرديا تجريبيا، وتأكد من عدم تكراره في الدفعة نفسها أو دفعة أخرى عند رفع CSV.

## حدود التحقق

نجحت فحوصات TypeScript وعمليات التحقق الثابتة. لم نتمكن من اختبار قاعدة Supabase الحية أو إعادة بناء Vite محليًا، لأن ملف المشروع المرسل يحتوي ملحقات Rollup الخاصة بWindows، لا Linux. GitHub Actions يستخدم `npm ci` على Ubuntu للبناء النهائي.
